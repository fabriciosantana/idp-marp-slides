# Ideia central

O GitHub não é só um repositório de código.

Ele pode funcionar como um **currículo verificável**, onde avaliadores conseguem observar:

- o que você constrói
- como você pensa
- como você documenta
- como você colabora
- como você evolui ao longo do tempo

<div class="callout">

**Pergunta do workshop**

Quando alguém abre seu GitHub hoje, que evidências encontra sobre o profissional que você quer se tornar?

</div>

# Critérios de uma presença forte

<!-- _class: compact -->

**Um perfil forte responde rapidamente:**

- quem é esta pessoa?
- que tipo de problema ela quer resolver?
- que tecnologias domina ou está aprendendo?
- que evidências mostram isso?
- como entrar em contato?
- o que ela está buscando agora?

**Um perfil fraco costuma deixar dúvidas:**

- projetos sem contexto
- README vazio ou automático
- nomes pouco informativos
- ausência de links
- perfil sem foco
- muitas promessas e poucas evidências

# Narrativa profissional

Uma boa narrativa para estudante não precisa parecer definitiva.

Ela precisa conectar:

1. **origem**: onde estou na formação
2. **interesse**: que problemas ou áreas me atraem
3. **evidência**: o que já construí ou estudei
4. **direção**: que oportunidade busco agora

<div class="small">

Evite frases genéricas como "apaixonado por tecnologia". Prefira uma formulação verificável: "estudante de Ciência da Computação com projetos em APIs, dados e automação".

</div>

# O que é o Profile README?

O GitHub mostra um README especial quando existe um repositório com o mesmo nome do usuário.

**Exemplo**

```text
github.com/aluna
github.com/aluna/aluna
README.md
```

Esse arquivo aparece na página principal do perfil.

<div class="callout">

**Função**

Dar contexto para quem está avaliando você antes que a pessoa precise interpretar seus repositórios sozinha.

</div>

---

# Estrutura recomendada

<!-- _class: compact -->

1. **Abertura curta**
   - nome, curso, área de interesse e objetivo atual
2. **Foco técnico**
   - linguagens, ferramentas e temas principais
3. **Projetos em destaque**
   - 2 ou 3 projetos com problema, tecnologia e link
4. **Evidências adicionais**
   - pesquisa, monitoria, eventos, artigos, cursos ou contribuições
5. **Contato**
   - LinkedIn, e-mail institucional, site ou currículo

<div class="small">

O perfil pode ser bilíngue, mas precisa ser consistente. Para oportunidades internacionais, uma versão em inglês ajuda.

</div>

---

# Template: Profile README

<!-- _class: compact -->

```markdown
# Olá, eu sou [Nome]

Sou estudante de Ciência da Computação na [instituição], com interesse em [área].
Atualmente busco [tipo de oportunidade] e estou construindo projetos em [temas].

## Foco atual

- [tecnologia ou área 1]
- [tecnologia ou área 2]
- [prática: testes, dados, backend, frontend, IA, segurança]

## Projetos em destaque

- [Projeto 1](link): problema, stack e resultado.
- [Projeto 2](link): problema, stack e resultado.
- [Projeto 3](link): problema, stack e resultado.

## Contato

- LinkedIn: [link]
- E-mail: [email]
```

# O avaliador abre um projeto

Ele precisa entender:

- que problema o projeto resolve
- por que o projeto existe
- como executar ou visualizar
- que decisões técnicas foram tomadas
- qual foi seu papel
- que limitações existem
- o que você faria a seguir

<div class="small">

Código sem contexto exige esforço do avaliador. README bom reduz esse atrito.

</div>

---

# Estrutura de README de projeto

<!-- _class: compact -->

```markdown
# Nome do projeto

Descrição curta do problema e da solução.

## Demonstração

Link, imagem, vídeo curto ou instrução de execução.

## Tecnologias

Lista curta com função de cada tecnologia.

## Como executar

Passos reprodutíveis.

## Decisões técnicas

Principais escolhas e justificativas.

## Aprendizados e próximos passos

O que foi aprendido, limites e melhorias.
```

---

# Requisitos para avaliação internacional

<!-- _class: compact -->

Para um projeto que pode ser visto fora do Brasil, considere:

- README em inglês ou bilíngue
- instruções de execução sem depender de conhecimento local
- licença definida quando fizer sentido
- ambiente reproduzível: `requirements.txt`, `package.json`, `Dockerfile` ou similar
- dados de exemplo ou indicação clara de como obtê-los
- imagens, GIF ou link de demonstração
- issues organizadas com próximos passos
- commits com mensagens compreensíveis
- explicação do seu papel em trabalhos em grupo

# Currículo online

O GitHub precisa conversar com outros pontos da presença digital:

- currículo em PDF ou página pessoal
- LinkedIn
- e-mail profissional
- portfólio
- Lattes, quando houver trajetória acadêmica
- ORCID, quando houver produção científica

<div class="callout">

**Consistência**

Área de interesse, projetos e links devem contar a mesma história em lugares diferentes.

</div>

---

# Currículo: versão mínima

<!-- _class: compact -->

Um currículo online inicial deve conter:

- nome e contato profissional
- formação
- objetivo ou resumo curto
- habilidades técnicas agrupadas por uso real
- projetos com links para GitHub
- experiência acadêmica, profissional ou voluntária
- cursos, eventos, pesquisa ou publicações relevantes
- idiomas

**Critério**

Cada item importante deve apontar para uma evidência ou resultado.
